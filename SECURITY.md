# Security policy

## Supported versions

| Version | Supported |
| --- | --- |
| 3.x | Yes. Fixes go into the next release from `main`. |
| 2.x | No. V2 is deprecated. |

Use the latest 3.x release. A fix is not backported to an older 3.x release.

## Report a vulnerability

Do not open a public issue, discussion, or pull request for a vulnerability.

Report it privately on GitHub:

1. Open the [Security tab](https://github.com/yungifez/skuul/security) of this repository.
2. Select **Report a vulnerability**.
3. Complete the form.

Include these details:

- The release tag or commit.
- The role and the campus setup that the problem needs.
- The steps that reproduce the problem.
- The data or access that the problem exposes.

Use fictional records in examples and screenshots. Remove credentials and personal data from logs.

## What happens next

1. A maintainer confirms the report.
2. The maintainer checks the problem and agrees a fix plan with you.
3. The fix goes into a release. The release notes and a GitHub security advisory describe the problem.

The advisory credits you, unless you ask for no credit.
